# 題材企画: 双方向関連の逆側だけを更新して外部キーが保存されない

## 対象と契約

Java 21、Spring Boot、Spring Data JPA、Hibernate、H2を使う実践・上級教材です。`Team#addMember`で追加した`Aki`は、チームの再読込で取得でき、`team_member.team_id`も保存済みチームを指さなければなりません。

## 直接原因と観測

一対多・多対一の双方向関連では多側が所有側です。逆側の`Team.members`へ追加するだけでは`TeamMember.team`が設定されず、外部キーがnullのままになります。契約テストは再読込したメンバー名と物理外部キー件数を分けて確認します。観測テストはnull外部キーを直接確認します。

## 新規性

既存のorphanRemoval題材は親から外した子の削除伝播を扱います。本題材は子を新規作成するときの関連設定と所有側の外部キー保存を扱うため、原因・境界・観測・修正が異なります。Repository Catalogは存在しないため、Qiita原稿と先行教材の語彙・四軸比較で代替調査しました。

## 履歴

1. 逆側だけを更新して外部キーが保存されない状態を再現する。
2. メンバーの所有側へチームを設定する。
